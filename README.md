# Kassa — свой аналог FunPay Pulse

Две части:

- **worker/** — сервер. Работает 24/7 на VPS в Docker, хранит аккаунты, собирает продажи, запускает плагины.
- **client/** — приложение для ПК. Только пульт управления: его можно закрыть, сервер продолжит работать.

Связь между ними шифруется (HTTPS), приложение проверяет отпечаток сертификата сервера и токен из ключа подключения.

## Как получить Kassa.exe

1. Создайте на GitHub **публичный** репозиторий, например `kassa`. Публичный нужен, чтобы сервер мог скачать установщик. Секретов в коде нет: ключи хранятся только на вашем сервере.
2. Загрузите в него все файлы проекта, включая скрытую папку `.github` (Add file → Upload files, или через GitHub Desktop).
3. GitHub сам соберёт программу за 3–5 минут: вкладка **Actions** → «Сборка Kassa.exe».
4. Готовый файл: вкладка **Releases** → «Последняя версия» → `Kassa.exe`.

После каждого изменения в папке `client/` exe пересобирается автоматически. Адрес вашего репозитория в команду установки подставляется сам, ничего править не нужно.

При первом запуске Windows может показать «Windows защитила ваш компьютер» — так бывает со всеми программами без платной подписи. Нажмите «Подробнее» → «Выполнить в любом случае».

Собрать exe на своём компьютере тоже можно: `client/build.bat` (нужен Python 3.12; перед сборкой замените `robinhilk488-bot/Lotus` в `client/main.py`).

## Первый запуск

Kassa.exe открывается с экраном «Установка сервера»:

1. Подготовьте VPS (Ubuntu 22.04+, от 1 ГБ памяти).
2. Подключитесь к нему: `ssh root@IP-сервера` в PowerShell.
3. Скопируйте команду установки кнопкой «Скопировать» и вставьте в окно сервера.
4. В конце установщик покажет **ключ подключения** `kassa_…`. Вставьте его в поле «Ключ подключения» и нажмите «Войти».

Ключ запоминается, в следующий раз приложение откроется сразу. Показать ключ ещё раз: `bash /opt/kassa/install.sh` на сервере. Эта же команда обновляет сервер.

Полезные команды на сервере:

```bash
docker logs -f kassa-worker          # логи
cd /opt/kassa && docker compose restart
```

## Разделы приложения

- **Сводка** — общий баланс, выручка и чистая прибыль за 30 дней, график, журнал.
- **Чаты** — переписка с покупателями всех аккаунтов, ответ прямо из приложения. Счётчик непрочитанных в меню.
- **Продажи** — выручка, чистая прибыль (минус комиссия и себестоимость), самые прибыльные лоты, таблица заказов.
- **Автовыдача** — лоты и товар: один текст всем или уникальная строка из списка (ключи, аккаунты). Себестоимость для расчёта прибыли.
- **Автоответы** — приветствие новым покупателям, вызов продавца командой `!help` (уведомление в Telegram), «спасибо» за отзыв.
- **Плагины** — встроенный каталог, включение переключателем, ключи API, проверка и пробный запуск.
- **Аккаунты** — аккаунты FunPay по golden_key.
- **Настройки** — уведомления в Telegram, автоподнятие лотов, чёрный список, комиссия, частота проверок.

## Уведомления в Telegram

Только сигналы на телефон, без управления. Подключение: @BotFather → `/newbot` → токен; @userinfobot → ваш ID; нажать «Запустить» у своего бота; вписать оба значения в Настройках и нажать «Отправить тестовое». Можно выбрать, о чём сообщать: заказ требует проверки, вызов продавца, аккаунт перестал работать, закончился товар, новый отзыв, заказ из чёрного списка, каждый новый заказ.

## Как защищена автовыдача

- Товар из списка закрепляется за заказом до отправки. Если отправка сорвалась, при повторе покупатель получит ту же строку — товар не тратится дважды.
- Закончился товар → заказ получает статус «Нужна проверка», приходит уведомление. Загрузите товар и нажмите «Повторить».
- Приветствие и автоответы не трогают переписки, которые были до подключения аккаунта.
- Покупателям из чёрного списка ничего не выдаётся и не отвечается автоматически.

## Аренда Steam (плагин RentSteam)

Готовый плагин. Раздел «Аренда Steam» в приложении.

Как работает: 1 купленная штука = 1 час, время идёт с оплаты. После оплаты покупателю уходят логин, пароль, срок и команды. В чате FunPay покупатель пишет:
- `!code` — код Steam Guard (генерируется из maFile, вам делать ничего не нужно);
- `!time` — сколько осталось;
- `!продлить` — плагин включает заранее заготовленный лот продления и даёт ссылку. Оплатил за 10 минут — часы добавляются, лот выключается. Не оплатил — лот выключается по таймауту.

Отзыв на 5 звёзд во время аренды даёт +1 час, один раз за всю аренду (продления входят в ту же аренду); повторные и изменённые отзывы бонуса не дают.

Когда время вышло: покупателю уходит сообщение, плагин меняет пароль аккаунта и проверяет, что новый пароль работает. Аккаунт освобождается только после успешной смены. Если смена не удалась (или у аккаунта нет maFile), он переходит в «Нужен сброс»: вы выходите на всех устройствах в Steam, при желании меняете пароль и нажимаете «Сброс выполнен». До этого аккаунт следующему покупателю не выдаётся.

Настройка: добавьте аккаунты (логин, пароль, maFile из Steam Desktop Authenticator), создайте на FunPay отдельный **выключенный** лот «Продление аренды» и впишите его ID в настройках плагина. Текущий пароль каждого аккаунта виден в приложении по кнопке «показать».

Важно: правила Steam запрещают передачу аккаунтов, такие аккаунты могут получить блокировку. Это риск для сдаваемых аккаунтов, а не для FunPay-аккаунта. Автоматический вход и смена пароля в Steam иногда ломаются при изменениях на стороне Steam — на этот случай аккаунт и уходит в «Нужен сброс», а не выдаётся дальше.

## Плагины: ключи API и защита денег

**Где вводить ключи.** Плагины → «Настроить». Поля типа `secret` (API-ключи, токены, пароли) шифруются на сервере и в приложение больше не возвращаются: видно только «Сохранён». Пустое поле при сохранении ключ не меняет, кнопка «Стереть» удаляет его. Плагин нельзя включить, пока не заполнены обязательные поля.

**Перед включением:**
1. «Проверить» — плагин проверяет ключ (например, запрашивает баланс у поставщика), ничего не покупая.
2. «Пробный запуск» — вводите название лота как на FunPay и смотрите, что плагин сделал бы. Ничего не покупается и не отправляется.
3. Один живой заказ на небольшую сумму, и только потом массовое включение.

**Как сервер защищает деньги:**
- Плагины получают только оплаченные заказы. Если заказ вернули до обработки, она отменяется.
- Каждый заказ записывается в очередь до обработки, поэтому при перезагрузке сервера он не теряется.
- Один заказ обрабатывается плагином ровно один раз.
- Сам сервер повторяет заказ, только если плагин сообщил, что ничего не успел сделать (`raise ctx.Retry(...)`), и не больше 5 раз.
- Любая другая ошибка, зависание или перезапуск посреди обработки → «Нужна проверка» (красный счётчик в меню и баннер на сводке). Вы проверяете, получил ли покупатель товар, и жмёте «Повторить» или «Выполнено вручную». Так исключается двойная покупка за ваш счёт.
- Заказы, оплаченные до подключения аккаунта, плагинам не отдаются — о них пишется предупреждение в журнал.

## Как добавить плагин в каталог (для разработчика)

Каталог — `worker/core/catalog.py`. Плагин из каталога, у которого нет файла, показывается как «В разработке». Чтобы он заработал, создайте `worker/plugins/<id>.py` с тем же id и обновите сервер (повторный запуск установщика). Полный пример с API-ключом, проверкой, лимитом цены и защитой от двойной покупки: `worker/plugins/_template_supplier.py`. Скопируйте его под новым именем и подставьте адреса из документации API поставщика.

Что есть у плагина:

| | |
|---|---|
| `ctx.config` | настройки (секреты уже расшифрованы) |
| `ctx.http` | requests-сессия с таймаутом 20 сек по умолчанию |
| `ctx.storage.get/set` | постоянное хранилище плагина (например, отметки о покупках) |
| `ctx.log(text, level)` | запись в журнал приложения |
| `ctx.dry_run` | `True` при пробном запуске — ничего не покупать |
| `raise ctx.Retry("причина", delay=60)` | безопасно повторить позже |
| `return ctx.SKIP` | заказ не относится к этому плагину |
| `def test(ctx)` | проверка подключения (только чтение) |
| `TIMEOUT = 120` | максимум секунд на один заказ |

## Подписка (продажа доступа к плагинам)

Базовый бот (чаты, продажи, автовыдача, аренда) работает всегда и бесплатно. Платной можно сделать только работу плагинов.

- Отдельный **сервер лицензий** ставится на твой VPS (папка `license-server/`, свой README).
- Клиент ставит воркер с адресом твоего сервера лицензий, получает **3 дня пробного периода**, а дальше активирует код в разделе «Подписка».
- Коды ты продаёшь через свои лоты на FunPay с автовыдачей: покупатель получает код в чат и вводит его в приложении.
- Код действует один раз, привязан к серверу клиента; продление суммируется; без подписки плагины не берут новые заказы, но дорабатывают начатые.

Если сервер лицензий не настроен (`KASSA_LICENSE_URL` пуст), подписка не требуется — это режим «для себя».

## Что важно знать

- Данные FunPay берутся из HTML-страниц. Если FunPay поменяет вёрстку, чинится `worker/core/funpay.py`.
- История продаж копится с момента добавления аккаунта: при каждой проверке сервер читает первую страницу продаж.
- Ключ подключения = полный доступ к серверу. Не публикуйте его. Чтобы сменить ключ: удалите `/opt/kassa/.env` и запустите установщик заново.
